Суть урока

Главная линия: агентам нужен не «умный чат», а организованный контекст, правила и источники.

1. Штаб — это точка входа

HQ хранит карту владельца, текущий фокус, задачи и ссылки на отделы. Это не свалка всех деталей, а кабинет руководителя, из которого агент понимает маршрутизацию.

2. Отдел — это рабочее пространство

Каждый отдел живёт в своей папке, имеет цель, правила, источники и материалы. Детали реализации остаются внутри отдела, а в HQ лежит ссылка и назначение.

3. Агент = LLM + инструменты

LLM генерирует текст. Чтобы она делала действия — читала папку, создавала файл, открывала браузер — ей нужна обвязка, инструменты и среда.

Ход обсуждения

Сжатая карта урока: от знакомства и организации курса до практики с первым отделом.

1

Интро участников и запросы

Участники описали свои области: видео, архитектурная визуализация, VFX, недвижимость, CRM, маркетинг, автономные процессы, личные ассистенты и цифровые копии.

2

Организация программы

ЛМС, Telegram-чат, Office Hours, записи, справочник и обновляемая база материалов. Отдельно обсуждался pipeline: запись Zoom → транскрипт → YouTube/страница → материалы.

3

Setup и инструменты

GitHub как хранилище знаний/доска для агентов, Obsidian как просмотрщик Markdown, Granola как источник транскриптов, терминальные агенты и Codex/Claude Code.

4

LLM, агент, tools, harness

Модель хорошо работает с текстом, но действия выполняет через инструменты. Harness даёт инструменты, среда определяет доступные возможности.

5

Практика «что в папке?»

Prompt показывает границу между памятью модели и реальным доступом к файлам. Важные приёмы: чистый контекст, просьба показать инструменты, Mermaid/TUI для визуализации логики.

6

Шаблон штаба и отдела

Минимальный HQ: `AGENTS.md`, `me.md`, `projects.md`, `tasks.md`, `README.md`/`CLAUDE.md`-ссылка. Дальше — один проект/процесс и постепенная персонализация.

Основные термины

Короткие определения из урока, адаптированные для повторения и работы агента.

Personal Corp

система

Личная компания из отделов, агентов, правил и источников.

Важно: переводит работу из разовых чатов в повторяемые процессы.

HQ / штаб

структура

Главная папка-контекст: владелец, фокус, задачи, индекс отделов.

Важно: агент стартует отсюда и понимает, куда идти.

Отдел

структура

Отдельная папка/проект с собственной целью, правилами и материалами.

Важно: детали не засоряют HQ и остаются рядом с работой.

Источник правды

гигиена

Единое место, где хранится подтверждённый факт или исходный материал.

Важно: меньше дублирования, меньше галлюцинаций.

Контекст

агенты

История, prompt, файлы, правила и среда, которые агент видит сейчас.

Важно: без контекста агент действует вслепую.

Чистый контекст

проверка

Новая сессия без старой истории.

Важно: показывает, что агент реально узнаёт из файлов, а что помнит из чата.

LLM

модель

Большая языковая модель, которая генерирует текст.

Важно: сама не читает папки и не кликает браузер.

Агент

система

LLM вместе с обвязкой, инструментами и окружением.

Важно: может выполнять задачи, а не только отвечать текстом.

Harness / обвязка

инфра

Слой, который даёт модели инструменты и управляет вызовами.

Важно: превращает модель в управляемую рабочую сущность.

Инструменты

действия

Программы и операции: shell, чтение файлов, запись, браузер.

Важно: через них агент видит и меняет внешний мир.

Окружение

среда

Компьютер, папка, права и доступные программы.

Важно: определяет реальные возможности агента.

Terminal / CLI

интерфейс

Текстовое управление компьютером командами.

Важно: идеально ложится на сильную сторону LLM — текст.

TUI / ASCII UI

визуализация

Интерфейс, нарисованный текстовыми символами.

Важно: помогает получать визуальную структуру прямо в ответе.

Mermaid

диаграммы

Текстовый формат схем и логических цепочек.

Важно: полезен для проверки рассуждения агента.

Plan mode

безопасность

Режим, где агент сначала показывает план.

Важно: даёт шанс остановить неверное действие до записи файлов.

Read-only

безопасность

Разведка без изменений.

Важно: первый безопасный шаг перед автоматизацией.

AGENTS.md

правила

Файл инструкций для агента в проекте.

Важно: задаёт границы, порядок чтения и маршрутизацию.

CLAUDE.md symlink

совместимость

Ссылка на AGENTS.md для Claude Code.

Важно: сохраняет один источник правил.

Obsidian

просмотр

Удобный просмотрщик/редактор Markdown.

Важно: не магия, а интерфейс к файлам.

GitHub как Notion

операционка

Репозиторий/доска как место, где агенты ведут знания и задачи.

Важно: даёт историю, issues, проекты и автоматизацию.

Browser control

инструмент

Управление браузером агентом.

Важно: полезно для залогиненных кабинетов, GitHub и рутины.

Prompt-интервью

метод

Агент задаёт вопросы по одному и предлагает варианты.

Важно: помогает вытащить персональный контекст из головы.

LMS

обучение

База записей, справочников и материалов курса.

Важно: позволяет пересматривать и обновлять знания.

Вопросы и ответы

Сначала попробуй ответить сам, потом раскрой «Ответ» и сверься с уроком.

Понимание системы

  1. Зачем нужен HQ, если уже есть отдельные проекты и папки?
    Ответ

    HQ даёт агенту единую точку входа: кто владелец, что сейчас в фокусе, какие отделы существуют и куда идти за деталями. Без штаба каждый чат начинается с нуля, а контекст рассыпан по папкам.

  2. Почему HQ не должен хранить детали реализации каждого отдела?
    Ответ

    Детали быстро устаревают и раздувают контекст. HQ хранит карту и ссылки — «один факт — один файл-владелец», — а подробности живут в отделе, рядом с самой работой.

  3. Чем отдел отличается от обычной папки с файлами?
    Ответ

    У отдела есть назначение, правила (AGENTS.md), источники и материалы — агент может работать в нём самостоятельно и предсказуемо. Обычная папка — просто хранилище без правил.

  4. Что значит «один источник правды»?
    Ответ

    Для каждого факта есть ровно одно каноническое место хранения. Остальные поверхности — dashboard, Obsidian, GitHub Issues — только отображают его, а не конкурируют с ним.

  5. Почему GitHub можно использовать как аналог Notion для агентов?
    Ответ

    Репозиторий, Issues и Projects дают историю изменений, задачи и автоматизацию через текст и CLI — форматы, с которыми LLM работает лучше всего.

  6. Почему Obsidian в этом setup — скорее просмотрщик Markdown?
    Ответ

    Obsidian удобно показывает те же Markdown-файлы, но связи и «память» задаёшь ты — правилами и projects.md. Магии поверх файлов нет.

Понимание агентов

  1. Что такое LLM и почему она сама по себе не «делает» действия?
    Ответ

    LLM — модель, которая генерирует текст по контексту. У неё нет «рук»: доступ к файлам, браузеру и командам появляется только через инструменты.

  2. Что превращает LLM в агента?
    Ответ

    Обвязка (harness), инструменты и среда. Возникает цикл: модель предлагает действие → инструмент выполняет его → результат возвращается в контекст → модель решает, что дальше.

  3. Что такое harness/обвязка?
    Ответ

    Программа-оболочка (Claude Code, Codex, Cursor), которая даёт модели инструменты, выполняет её вызовы и возвращает результаты обратно в контекст.

  4. Почему инструменты агента удобно описывать через текст?
    Ответ

    Вызов инструмента и его результат — это текст: команда → вывод. Это совпадает с сильной стороной LLM — работой с текстом, поэтому shell-команды и API ложатся на неё естественно.

  5. Почему терминал хорошо подходит агентам?
    Ответ

    Терминал полностью текстовый: команда на входе, текст на выходе. Агент управляет компьютером тем же способом, каким «думает».

  6. Почему модель без инструментов не может честно ответить, что в папке?
    Ответ

    Без вызова инструментов у модели нет доступа к файловой системе — она ответит из памяти чата или придумает. Честный ответ: «мне нужны инструменты, чтобы посмотреть».

Понимание процесса

  1. Зачем запускать prompt в чистом контексте?
    Ответ

    Чистый контекст отделяет то, что агент реально узнаёт из файлов, от того, что он помнит из текущего чата. Это проверка воспроизводимости твоей настройки.

  2. Что показывает plan mode?
    Ответ

    План действий до записи на диск: какие файлы агент создаст или изменит и почему. Ошибку можно остановить до того, как она случилась.

  3. Почему read-only разведка безопаснее записи?
    Ответ

    Чтение ничего не ломает: сначала индексируем существующий хаос, потом меняем — по плану и с разрешения владельца. Оригинал остаётся цел.

  4. Как Mermaid помогает увидеть логику агента?
    Ответ

    Агент рисует цепочку рассуждений и вызовов инструментов диаграммой — маршрут виден до выполнения, и ошибки логики заметны сразу.

  5. Почему важно читать план агента перед выполнением?
    Ответ

    Минута на чтение плана дешевле переделок и откатов — особенно на дорогих моделях. Прочитанный план — это осознанное разрешение, а не слепое доверие.

  6. Почему персонализацию лучше начинать с одного процесса?
    Ответ

    Маленький контур быстрее доводится до рабочего состояния и даёт паттерн для масштабирования. «Сразу всё» = размазанный контекст и хаос.

Практические prompts

Формулировки, которые обсуждались на уроке и сразу применимы в HQ/отделах.

Проверить папку и инструменты

Что ты видишь в этой папке?
Перед тем как отвечать, расскажи прямо в чате, какие инструменты ты хочешь вызвать,
и нарисуй логическую цепочку в формате Mermaid.

Проверить границу без инструментов

Не используй инструменты. Что ты видишь в этой папке?

Ожидание: модель признаёт, что без инструментов не может заново посмотреть файловую систему.

Интервью для персонализации

Проведи со мной интервью по каждому из вопросов,
пока мы не придём к общему пониманию.
Иди по одному вопросу за раз.
Для каждого вопроса предлагай рекомендованные варианты ответа.
Если можешь сам найти ответ через исследование файлов — сделай это и не спрашивай меня.
Не начинай реализацию, пока мы не пришли к общему пониманию.

Добавить проект в HQ

У меня есть проект рядом с HQ. Добавь ссылку на него в HQ:
путь, назначение, правила и статус. Детали проекта оставь внутри проекта.
